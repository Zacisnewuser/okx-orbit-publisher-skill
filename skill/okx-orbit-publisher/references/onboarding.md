# 聊天引导与配置

## 初次对话

先读取已存设置，缺什么才问什么。不要一次要求填写全部字段。

1. 确定眼前目标：先准备文案、手动发布、还是定时运营。未选择时先准备一份草稿。
2. 从用户描述提取账号定位、语言、语气、禁用话题；不要求用户提供内部 UID 或私有账户信息。
3. 发帖与评论分别保存提示词和内容模式：`fixed` 固定文案、`ai` 生成、`mixed` 固定首尾加生成内容。没有浏览器时评论必须使用用户提供的原帖内容，并标记待在线核验。
4. 手动发布需要浏览器能力；定时运营另外需要宿主调度能力。依照 capabilities.md 分步引导安装和验收。
5. 用户手动在 Chrome 登录星球、完成人脸等验证；读取公开账号 ID 和名称让用户核对，登记已验证星球 URL 范围。
6. 展示一份草稿和可读设置摘要：账号风格、启用功能、时间/时区、执行模式、每日上限。预览通过后保存模拟验收时间。
7. 只有用户要求正式运行才切换模式、解除暂停。`confirm` 展示具体目标与完整草稿获批后提交；`auto` 在用户授权的功能、时间及规则内自动审核，不重复问每条是否批准。

例：“我可以先帮你写一份草稿。你希望账号偏专业分析，还是轻松交流？”如果上下文已经给出偏好则直接写。

## 用聊天改设置

“评论短一点”修改评论风格；“以后晚上八点发”修改发帖时间，时区已有则沿用；“只帮我写，别发布”切换 dry-run 并暂停公开执行；“暂停”走全局暂停流程。

将变化通过 `configure` 保存，简短报告前后差异。内容规则、名单、模式或账号变化会让未执行批准失效，重新检查草稿。运行中的任务只核验结果，不改正文。新设置影响后续任务，不能重发历史内容。

调度时间修改属于两阶段操作：先保存意图，再让外部调度工具修改已登记任务；记录验收结果。工具不可用时报告“时间已保存，定时服务尚未更新”，不要声称已经按新时间运行。

## 默认与个人选择

首次 `paused=true`、`mode=dry-run`；关系管理默认关闭；发帖/评论提示词和固定首尾默认空。默认每日上限为发帖 2、评论 20、点赞 20、关系动作各 5，相邻公开动作至少 30 分钟；这是可修改的初始设置，不是新用户已有授权。

用户可以调整配置。数量永远是上限，缺少适合内容就少发。活跃窗口和更长间隔由调度适配遵守，不用随机行为规避平台限制。固定内容模式无需独立模型；默认使用宿主 Agent 的模型。

不要自动导入另一位用户的人设、账号、名单、话术、授权或时区。检测到已有项目时保留其个人规则；规则冲突按最近的明确用户设置处理，暂停和未知提交不得被旧配置覆盖。
