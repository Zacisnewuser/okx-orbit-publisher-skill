# 安装、升级与迁移

## 给用户的简单说明

“把整个 okx-orbit-publisher 文件夹交给你的 Agent，告诉它：读取 SKILL.md，带我开始使用。”

macOS 为当前目标平台。Skill 需要宿主能读取本地文件；持久化/执行还需运行 Python 3.9+。先检查能力，缺失时依照 capabilities.md 提供适合该 Agent 的外部工具安装指引。分发包不带浏览器或调度 Skill，也不自动安装扩展、开机服务或唤醒任务。

Codex 可以按它支持的本地 Skill 安装机制安装目录；Hermes/OpenClaw 等通过各自官方技能安装流程安装或直接让 Agent 阅读目录。`agents/openai.yaml` 只是 Codex 的可选显示信息，其他宿主可忽略。不同宿主真实接入还需要能力验收，不能仅凭文件格式声称全部已经兼容测试。

## 数据分离

版本更新只替换代码与通用说明。配置、人设、时间、名单、任务、历史均在用户独立数据目录。不得在安装时写入作者的账号、绝对路径、授权、自动化 ID 或历史数据。

发现旧版本/既有项目时，先备份安装目录和本地状态；设置 `legacy_project_path` 到用户实际项目目录，读取其暂停及个人规则。旧历史只保留在用户机器，恢复执行前联合去重核验，不按新用户默认配置重启旧任务。安装新版不会自动升级旧调度提示词，也不会重新启用暂停任务。

## 更新与回滚

1. 本地 pause，暂停并核验已登记外部任务；若有 executing/unknown 先只读核验，不能通过更新抹掉。
2. `backup` 创建新备份文件，另外复制 discovery/metrics/notifications 等侧文件。记录 Skill 版本、数据库 schema 和备份时间。备份含运营记录，不能夹入可分享安装包。
3. 保留旧 Skill 完整目录，检查新包来自用户认可来源；有发布校验值时验证，之后替换安装文件。
4. 运行新版本 `doctor` 和离线检查；设置与历史必须仍在。数据库 schema 不支持时停止读取写入并使用兼容版本；不得删除重建。未来迁移须显式提供迁移程序和前置备份，不宣称当前已经具备任意版本迁移能力。
5. 更新后维持暂停。用户要求恢复后重新验收；回滚只换回兼容 Skill 文件，不能用旧数据库覆盖较新提交历史。

## 恢复备份/换电脑

先停用原位置所有写入与调度，保存当前数据作为可恢复副本。工具只允许恢复到新目录，并强制暂停；unknown/executing 仍保留。备份之后可能发生过的公开动作必须通过旧日志和公开页面核对后补齐，未核清不能正式恢复。

告诉所有 Agent 新的共享路径，防止旧副本继续运行。不要合并两个数据库或简单丢弃未知任务。浏览器登录不随备份迁移，需要用户手动重新登录；新的机器需重新验收浏览器和调度能力。

## 打包给别人

仅分发 SKILL.md、agents/openai.yaml、references、scripts 和 LICENSE。不要分发本地数据库、legacy_project_path、个人配置、队列、运行日志或历史安装备份。用户可用“先写一份草稿”“开始配置”“检查为什么没运行”“暂停”“看看效果”作为入口。
