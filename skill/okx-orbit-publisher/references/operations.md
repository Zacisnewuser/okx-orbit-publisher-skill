# 内容与互动流程

## 内容

按个人配置分别应用发帖/评论提示词、语言、风格、禁用话题和 fixed/ai/mixed 模式。涉及当前事实时核验公开来源与时间；没有资料先做待核验草稿，不编造。用户提供的公开摘要可以使用，不读取交易账户或未公开策略。默认不使用持仓卡。

发帖围绕一个明确主题，使用相关真实话题。午间投票、晚间复盘是可选内容模板，不强制任何用户 12:00/21:00 发布，也不承诺一定有后续结果。评论回应原帖一个真实细节，避免复制、空泛赞美和虚构经历。

普通市场方向观点不自动导致整篇拒绝；评论可以只谈其方法、纪律、数据口径或验证方式，不背书买卖方向。诈骗、收益保证、喊单拉群、攻击违法内容和无法形成自然中立回应的帖子拒绝。

固定首尾由个人配置决定，默认没有“互动互动”话术。启用混合模式时严格保留用户的首尾和换行，检查中间内容具体、不重复。保存一个主策略标签供后续比较。

## 候选发现

先保存日期、时区、generation 状态和断点，再浏览。默认目标 25 个候选、缓冲 5、每日筛选最多 240 篇，属于可调搜索预算，不是评论配额。

采用多来源轮询：互动活动、最新公开帖、热门/活动话题、复盘、风险纪律、数据/项目方法、推荐流。尽量覆盖六类实际可用来源，每个来源连续最多 8 篇；其他来源可用时单源候选占比最多 30%。连续 10 篇重复/无候选时标记低产换源。来源不足记录原因，不假造覆盖率。

按 post_id 和 author_id 去重，默认同作者每天一个候选。每条筛选后保存来源、通过/拒绝原因、计数和断点到本地 `discovery-日期.json`；临时文件加原子替换，生成器也必须持有外部会话锁。单轮约 8 分钟内保存 `ready/ready_partial`；不要让 building 候选可执行。缺队列/超时/耗尽时只恢复补筛，该轮不提交。

旧项目若仍绑定特定时间避让或筛选规则则沿用；新用户通过串行调度与执行锁协调，不硬编码原账号时间。

## 一次执行

1. 读取状态、个人配置和候选；确认未暂停、模式允许、任务未过期、未重复且额度/间隔允许。
2. 获取本地会话锁（state.md），重新读取账号、目标、正文、URL、登录、验证码和关系。检查个人黑/白名单；白名单不绕过内容审核或保护名单。
3. 对新候选调用 `enqueue`，保存正文、对象/作者 ID、来源、标签、过期时间；队列已有任务则沿用其 ID，不再次入队。修改尚未尝试草稿的正文时，先 `cancel` 旧稿，再以新 ID 排队重审。给用户批准的对象必须和即将发送的对象完全相同。
4. confirm 模式根据用户对具体草稿的批准调用 `approve`；auto 模式只对已授权功能且全部检查通过的候选调用 `approve`。任务批准保存配置版本，配置变化后须重新检查。
5. 调用 `claim` 取得持久化唯一执行许可。只有调用成功且 ID 匹配才能点击一次。`claim` 后任意不确定情况不可重新 claim。
6. 公开核验：帖子/评论匹配当前作者、正文、目标及稳定 ID/链接；点赞/关系匹配目标状态变化。调用 `finish verified` 写证据，创建 24/72 小时检查；页面/回执不明则 `finish unknown`。提交前确定未点击的失败可 `finish not_submitted` 并写理由。
7. 释放会话锁。中断或进程崩溃后 `executing` 保持锁定；新 Agent 先只读核验并解决旧任务，不重试提交。

每轮最多一项公开动作。评论后同帖点赞可作为第二个独立任务记录，仅个人策略明确允许组合且满足各自门禁时执行；默认按普通冷却时间排队。不要把点赞成功推断为评论成功。

状态工具不做语义相关性、页面内容真假或名单审核，Agent 要按上述流程执行；它负责精确/规范化去重、状态流转、配置版本、额度、间隔和并发许可。近似语义去重结合已有任务正文人工/模型检查。
