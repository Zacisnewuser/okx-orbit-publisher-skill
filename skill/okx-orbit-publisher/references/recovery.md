# 自检、暂停与恢复

用户说“检查一下为什么没运行”时，先运行本地 `doctor`，再按实际需要检查外部能力。不为了诊断触发发布。

| 原因 | 核验依据 | 给用户的处理提示 |
|---|---|---|
| 用户暂停/dry-run | 本地模式、暂停原因 | 当前只准备草稿，收到恢复要求才启动 |
| 登录、人脸或验证码 | 可见页面提示 | 请在 Chrome 手动完成验证，完成后告诉我继续 |
| 浏览器控制断连 | 工具只读连接失败 | 按该工具说明恢复连接，再核对账号 |
| 调度未启用/时间不一致 | 调度工具实际状态/下次时间 | 指出哪项定时尚未生效，保留手动使用 |
| 电脑休眠/会话退出 | 系统或调度运行记录 | 只报告有证据的情况，不把所有延迟归因于休眠 |
| 额度/冷却/候选过期 | 本地任务、设置和时间 | 告知下次可运行条件；不集中补发 |
| 网页结构变化/越界 | URL、唯一元素定位、可见页面 | 停止该浏览器操作并记录待修复点 |
| executing/unknown | 持久化任务 ID 和记录 | 先核对旧提交结果，禁止再点击 |

`doctor` 只检查本地数据库与配置，不证明 Chrome 登录/外部调度健康。浏览器只读连接诊断限制一次，失败后保存原因，避免每次心跳重复重连与通知。用户明确要求重查或状态改变后可再次只读检查。

## 暂停

立刻 `pause` 保存原因，然后按调度登记表逐项暂停。已有 submitting/executing 只完成只读核验并记结果。外部调度停用失败明确告知，新的统一门禁仍阻止接入它的任务。旧自动化可能未接门禁，要单独停用确认。不要退出 Chrome、登出账户或停止不属于本 Skill 的服务。

## 恢复

用户明确要求后：检查原暂停原因 → 用户手动完成必要验证 → 重连浏览器并核对公开账号 → dry-run 预览 → 处理未知结果 → 保存短期 preflight 验收 → 按用户选择启用模式/功能 → 恢复已登记调度并读回验收。

历史 preflight 在暂停、改设置、升级和恢复备份后失效。实时页面检查每次提交重做。过期草稿/候选重新读取原帖和时效，重审后创建新任务；错过的定时槽默认跳过，不突击补发。

## 已提交但不确定

将其记为 unknown；若中断来不及写 unknown，executing 同样锁住。通过只读公开证据查到对应对象则完成 verified。只有用户明确确认未提交后才能 `resolve-absent`，保留审计并将原任务终结为 not_submitted；后续重做必须使用新任务 ID、重新审核及取得授权。查不到不等于未提交。

## 降级与通知

断连后仍可写稿、修改设置、查看本地记录；暂停外部执行。对同一原因和相同影响只通知一次，在 `notifications.json` 保存指纹/最后通知时间；用户询问时正常答复，恢复或发生新问题时再更新。回答用“状态、影响、最小处理动作”，不要用堆栈替代解释。
